# 架构与维护

## 运行方式

前端是无构建的原生 ES modules，服务端使用 Node 标准库。浏览器能力与业务规则分开，第三方测试工具只作为开发依赖。纯静态部署保留本地功能；Node 部署增加同源地图和天气代理。

```text
app.js                     启动、路由、模块组装、跨标签状态通知
data.js                    静态菜单、稳定图片槽位、餐次补充数据
config.js                  公开 API 地址、可选推广入口
src/core/
  model.js                 模型、上限、日期、版本、导入校验
  catalog.js               菜单合并、参考标签、旧快照补全
  selection.js             统一筛选、加权抽取、指针、计划生成
  storage.js               迁移、不可变状态、单键保存、订阅
  backup.js                完整备份与菜单文件契约
  images.js                无网络名称卡
  photos.js                原图候选、明确菜名/品类实物参考图
src/ui/                    图标、卡片、图片加载、原生弹窗、Canvas
src/features/              决策、附近、菜单、计划、收藏/记录、设置
src/services/              API、外卖跳转、分享图片、音效/摇一摇、PWA
server/app.js              HTTP 路由、文件白名单、限流和有界缓存
server/providers.js        固定上游访问、坐标转换、POI/天气校验
server/index.js            配置、监听、HTTPS 与退出
sw.js + sw-assets.js        按站点路径与版本隔离的完整离线应用壳
tests/                     纯逻辑、HTTP、浏览器与 Python 素材测试
```

## 数据契约

`chishenme:state:v1` 包含 schemaVersion、favorites、history、customFoods、menuOverride、plan、preferences 和 settings。位置、网络状态、当前标签、旋转动画和 API 密钥不属于持久化业务数据。

- 菜品以稳定 ID 识别，同时保留快照；菜单删除后，已有收藏、记录和计划仍能显示。
- 内置菜品 ID 根据规范化名称生成；编辑自定义菜品保留原 ID。
- 自定义菜单和替换菜单是两个独立集合，替换模式新增/编辑写入替换集合。关闭替换模式后原自定义集合仍在。
- `store.update` 在克隆上修改，校验成功后一次写入单个 localStorage 键，再发布不可变快照；写入失败不崩溃，继续使用会话状态并提示备份。
- 同源其他标签页通过 storage 事件同步。它不是云同步或多用户数据库；不同来源、设备不自动合并，备份用于迁移。
- 新数据损坏时保留原文，在下次成功保存前写入恢复键；不删除旧版键。
- 上限为收藏/自定义集合 500 条、记录 300 条、计划 366 个日期、导入文件 2 MB。

## 选择与计划约束

顺序为候选源 → 餐次/分类 → 硬偏好与关键词 → 权重。最近选择、清淡优先和天气只影响机会，不会绕过硬过滤。避免重复在有其他候选时直接排除上一项。

转盘结果先从完整候选池选择，再生成包含结果的最多 8 项盘面。整数整圈加目标扇区中心角确保指针对齐。Canvas 缓存静态扇区，Web Animations 对画布、照片父层与反向菜名层执行 1750ms 旋转，动画期间不逐帧重画；落定才重画选中扇区。同一菜品复用照片节点。中心、主抽取及直接选择按钮在抽取中锁定。主题改变时失效缓存，减少动态效果或不支持 Web Animations 时直接落定同一结果。

计划以本地日期为键，避免 UTC 日期偏移。自动生成尽量不重复，候选耗尽才在合格候选内复用并提示；无候选保留空位或现有安排。锁定和已吃的餐次不被重排。内置甜品饮品不作为独立自动计划餐；手动添加仍由用户决定。

修改偏好不会擅自删掉既有计划；冲突会显示在计划中。打卡与选择分开，计划打卡使用稳定记录 ID，撤销不会制造重复历史。

## 网络和界面边界

- 只有点击定位才申请权限，新的定位/范围请求使旧请求失效；取消后的迟到响应不能再次切换附近模式。
- 服务端只访问高德和 Open-Meteo 固定主机，不接受任意转发 URL。经纬度、范围与请求方式先校验。
- API 每个客户端每分钟最多 40 次，最多 2 个未缓存任务，重复请求合并；缓存最多 100 个键、有效 5 分钟。上游响应最多 1 MB，有单次与整体超时。
- 错误响应不包含密钥、上游 URL 或内部堆栈。允许跨域时只返回精确匹配的 `ALLOWED_ORIGIN`。
- 外卖入口同步打开 HTTPS 页面，复制另行反馈，避免等待剪贴板后被浏览器拦截弹窗；不声称能自动下单或领取优惠。
- 图片依次尝试最多 5 张上游原图，再回退到明确菜名/品牌/品类对应的已有实物参考图。`displayPhotoCandidates` 仅为显示附加 WebP/srcset，保存与备份继续使用原图字段。每个本地 WebP 后紧跟对应 JPEG 兜底；全部失败才显示名称卡。
- 本地图使用浏览器原生懒加载、响应式资源和解码，主图为高优先级、转盘为 160px 低优先级；不再同时创建本地 Image 预加载。远程原图仍通过 IntersectionObserver 与最多 6 个并发探测，在成功前保留参考图，并支持恢复联网重试。分享遵循原图候选顺序和参考标注。
- 隐藏页面按首次访问初始化；收藏和配色只更新必要控件，保留照片节点。菜单默认展示 24 道，用户可继续加载；90ms 搜索合并输入并尊重中文输入法组合，筛选覆盖完整菜单。
- 首屏在 HTML 中预留照片、正文、图标和餐次控件尺寸，关键模块预加载，使内容就绪时保持布局稳定。
- 弹窗使用原生 dialog，动态替换内容时恢复合适焦点；关闭后按稳定控件属性找回入口。异步分享生成以 generation 检查避免覆盖新弹窗。

## 离线和更新

每个应用路径具有自己的 shell/image 缓存前缀。安装时完整缓存模块清单；运行时应用壳缓存优先，保证页面与模块属于同一版本。更新在用户确认后接管。只清理本应用缓存；旧版无前缀缓存也要检查所属页面后才删除。

API、运行配置和个人数据不进入 Service Worker 缓存；照片单独缓存在 images-v2，最多 240 个资源。WebP 与 JPEG 都在同源照片路径下缓存。开发模式注销本应用的 Service Worker 后重新载入，避免修改被旧应用壳隐藏。

新增浏览器模块后更新 sw-assets.js，`npm run check` 会验证遗漏、文件存在性、版本一致性和内置图片槽位。发布前按 README 运行所有检查。
